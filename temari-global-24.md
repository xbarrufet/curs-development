

**Pla General de 24 Setmanes (Evolució Paulatina de Treball)**
Aquest es un pla de formacio per un developer junior a les noves formes de treballar actuals, inclou temes d'algoritmica, AI-SDLC, prompt engineering i orquestració d'agents.

**Competència Transversal: Prompt Engineering**
El prompt engineering no es treballa en una setmana aïllada sinó que es practica de forma progressiva al llarg de tot el pla:
- **Bloc 1:** Redacció de prompts clars per obtenir codi correcte dels assistents (instruccions, constraints, exemples).
- **Bloc 2:** Tècniques d'output estructurat (few-shot, schema enforcement, system prompts).
- **Bloc 3:** Prompt engineering per a knowledge retrieval (chain-of-thought, prompts de citació, anti-al·lucinació).
- **Bloc 4:** Disseny de prompts per agents autònoms (role prompts, tool-use prompts, guardrails).
- **Bloc 5:** Redacció d'especificacions per agents de codi (`CLAUDE.md`, `.cursorrules`) com a forma avançada de prompt engineering.

**Competència Transversal: Python com a Segon Llenguatge**
Python s'introdueix gradualment des del Bloc 1 per evitar el salt brusc a S8:
- **Bloc 1 (S1-S4):** Exercicis paral·lels en Python dels mateixos conceptes (Big-O, estructures, testing). L'estudiant veu que els algorismes són agnòstics del llenguatge. Java és el principal, Python és el "mirall".
- **Bloc 1 (S5-S6):** Setup de l'entorn Python (`venv`, `pip`, `pytest`). Exercicis de testing en Python paral·lels als de Java.
- **Bloc 2 (S7-S10):** Python pren protagonisme al costat IA (FastAPI, Pydantic) mentre Java manté el backend REST.
- **Bloc 3-5:** Python és el llenguatge principal per a IA/Knowledge/Agents; Java és el backend de dades.

**Competència Transversal: Ecosistema d'Eines IA (Skills, Plugins, MCP, Hooks)**
Les eines d'IA no són un chatbot — són plataformes extensibles. Però les eines es presenten **quan l'estudiant té el problema que resolen**, no abans. Primer el dolor, després la solució:
- **Bloc 1 (S2):** `.cursorrules` com a part natural de l'exercici de convencions SOLID — no s'ensenya com "configuració d'eina IA" sinó com "definir les regles del projecte". Que l'assistent les consumeixi és un benefici lateral, no l'objectiu.
- **Bloc 1 (S4):** Hooks de Git (`pre-commit`) per executar Checkstyle/ruff automàticament. Connexió conceptual: un hook és un "guardrail automàtic" — el mateix patró que es reutilitzarà amb agents.
- **Bloc 2 (S8):** Després de setmanes copiant-pegant resultats SQL a l'agent, s'introdueix MCP (Model Context Protocol): instal·lar `mcp-server-sqlite` perquè l'agent consulti la BD directament. Ara l'estudiant entén el VALOR perquè ha viscut el dolor.
- **Bloc 2 (S9):** MCP pràctic: crear un MCP server senzill en Python que exposa `search_logs()`. L'estudiant veu que crear un MCP server és un wrapper HTTP sobre una funció Python amb un schema JSON.
- **Bloc 3 (S11):** Com trobar skills, plugins i MCP servers existents (veure secció detallada a sota). L'estudiant ja sap què és un MCP server i pot avaluar-ne de tercers amb criteri.
- **Bloc 4 (S15):** Tool use en agents: entendre que el loop agent→eina és el mateix patró que MCP. Dissenyar l'schema d'eines per als agents de GamePulse.
- **Bloc 4 (S18):** Crear un skill personalitzat (`/review-gamepulse`). Hooks de Claude Code (`post-tool-call`). Ara l'estudiant ha fet prou code reviews manuals per saber exactament què vol automatitzar.
- **Bloc 5 (S19):** Consolidació: skills, MCP servers i hooks documentats al `CLAUDE.md`. Un developer nou pot clonar el repo i tenir l'entorn IA complet funcionant.

**Com Trobar i Avaluar Skills, Plugins i MCP Servers**
Una de les habilitats més pràctiques d'un developer que treballa amb IA és saber trobar eines existents en lloc de construir-les de zero. Igual que un developer busca llibreries a npm/PyPI abans de reimplementar, un developer IA busca skills i MCP servers abans de crear els seus:

**On buscar:**
- **MCP Servers:** [modelcontextprotocol.io/servers](https://modelcontextprotocol.io) — el registre oficial. Filtra per categoria (databases, APIs, dev tools). GitHub: busca `mcp-server-` per trobar implementacions comunitàries. Dins de Claude Code: `/mcp` mostra els servers configurats; la documentació oficial de Claude Code llista els recomanats.
- **Skills de Claude Code:** El directori `.claude/skills/` del projecte conté skills locals. Skills comunitaris es comparteixen com a repositoris Git (clonar a `.claude/skills/`). Claude Code inclou skills built-in (`/code-review`, `/init`, `/security-review`) — explorar-los amb `/help`.
- **Cursor Rules / Extensions:** [cursor.directory](https://cursor.directory) — repositori comunitari de `.cursorrules` per frameworks específics (Spring Boot, FastAPI, React). VS Code Marketplace per extensions que integren amb IA.
- **Plugins i Integracions:** Cada eina IA té el seu ecosistema — Claude Code té skills i MCP; Cursor té extensions i rules; GitHub Copilot té plugins. La clau és buscar al lloc correcte per cada eina.

**Com avaluar si un skill/plugin val la pena:**
1. **Manteniment:** Última actualització fa menys de 3 mesos? Si no, probablement incompatible amb la versió actual de l'eina.
2. **Stars/ús:** No cal que sigui popular, però zero ús és risc.
3. **Seguretat:** Un MCP server té accés a les teves dades. Revisa el codi font abans d'instal·lar — sobretot si demana accés a BD, fitxers, o APIs amb credencials.
4. **Scope:** Fa una cosa bé o intenta fer-ho tot? Prefereix eines petites i especialitzades.
5. **Prova-ho:** Instal·la'l en un projecte de prova, no directament al projecte real. Verifica que fa el que promet.

**Exercici pràctic (S11):** Buscar i instal·lar:
- Un MCP server per interactuar amb la BD de GamePulse (probablement `mcp-server-postgres` o `mcp-server-sqlite`).
- Un skill o `.cursorrules` per al framework que estiguem usant (Spring Boot rules, FastAPI rules).
- Avaluar un MCP server comunitari per a Qdrant — existeix? És fiable? Si no, justificar per què caldria crear-ne un.
- Documentar al `CLAUDE.md` del projecte: quins skills/MCP servers s'usen, per què, i com instal·lar-los.

**Competència Transversal: Escriptura de Specs per a Agents**
L'escriptura d'especificacions es practica de forma progressiva. Escriure una bona spec és la forma més avançada de prompt engineering — definir QUÈ vols que l'agent faci, amb quines restriccions, i com verificar-ho:
- **Bloc 1 (S2):** `.cursorrules` inicial: convencions de codi, noms, estructura. L'estudiant entén que un fitxer de text dirigeix el comportament de l'assistent.
- **Bloc 1 (S4):** Primer exercici formal: escriure una spec perquè un agent refactoritzi un mòdul concret. Comparar el resultat amb la refactorització manual. Iterar la spec fins que el resultat sigui acceptable.
- **Bloc 2 (S7):** Spec per a generació d'endpoints REST: definir contractes (input/output/errors) en un format que l'agent pugui consumir. L'estudiant genera controladors a partir de la spec i audita el resultat.
- **Bloc 2 (S10):** Spec per a generació d'interfície Streamlit: descriure el dashboard desitjat amb wireframes en text. L'agent genera; l'estudiant revisa i itera.
- **Bloc 3 (S13):** Spec de comportament per al sistema de knowledge retrieval: "donada aquesta pregunta, ha de retornar X amb citació de Y". Format de test-spec que es pot automatitzar.
- **Bloc 4 (S15):** Spec d'agent complet: role prompt, eines disponibles, guardrails, format de resposta. Exercici amb OpenSpec/SpecKit: documentar l'agent perquè un altre developer el pugui entendre i modificar.
- **Bloc 5 (S19):** Consolidació: `CLAUDE.md` + `.cursorrules` finals. Exercici avaluat: donar una spec a l'agent i mesurar si el codi generat passa els tests escrits a la spec.

**Bloc 1: Fundaments, POO i Concurrència en Java + Python (80% a mà / 20% assistit)**

* **Setmana 1 (Rendiment i Big-O):** Programació a mà de cerques $O(n)$ en `List`/`list` vs $O(1)$ en `HashMap`/`dict`. *Exercici Python:* El mateix benchmark amb `list` vs `dict` — comparar resultats entre JVM i CPython. *Lliurament:* Executable de benchmarking en Java 21 + script equivalent en Python.
* **Setmana 2 (POO i SOLID):** Creació a mà de models immutables (`records` / `@dataclass(frozen=True)`) i regles d'arquitectura a `.cursorrules`. *Exercici Python:* `GameRecord` com a `dataclass` frozen, `GameRepository` amb `abc.ABC`. *Exercici Specs:* Escriure un `.cursorrules` complet per al projecte: convencions de noms, estructura de carpetes, regles d'immutabilitat. Verificar que l'assistent respecta les regles en generar codi. *Lliurament:* Domini `GameRecord` i interfícies `Repository` en Java + equivalents Python.
* **Setmana 3 (Concurrència Pràctica per a Developers Web):** Race conditions, `@Transactional`, `CompletableFuture` i Virtual Threads (Java). *Exercici Python:* Race condition amb `threading`, solució amb `asyncio` + `aiohttp` per I/O paral·lel — el patró equivalent a CompletableFuture. *Lliurament:* Extractor paral·lel d'APIs Steam/IGDB en Java + versió asyncio en Python.
* **Setmana 4 (Clean Code, Code Review, Git Workflow & CI):** Refactorització d'anti-patrons pràctics en codi generat per IA (seguretat, nulls, tests buits), code review com a skill, `rebase` de Git, resolució de conflictes, i GitHub Actions bàsic (`mvn test` + `checkstyle`). *Exercici Python:* Auditar snippets Python generats per IA (f-strings amb SQL injection, `except: pass`, imports no usats). *Exercici Specs:* Escriure una spec de refactorització i donar-la a l'agent; iterar fins que el resultat sigui equivalent a la versió manual. *Exercici Eines IA:* Configurar un hook `pre-commit` de Git que executa Checkstyle i ruff automàticament — entendre que un hook és un "guardrail" que s'executa sense intervenció humana, igual que els guardrails d'agents. *Lliurament:* Tag de versió `v0.1` en repositori estructurat, amb badge de CI al README.
* **Setmana 5 (Patrons Factory, Repository i Persistència JPA):** Disseny a mà de la jerarquia d'interfícies per desacoblar l'accés a dades. Introducció a Spring Data JPA amb H2. Exercici SQL pur: escriure les queries equivalents a mà a la consola H2 (SELECT, WHERE, JOIN bàsic). *Exercici Python:* Setup definitiu de l'entorn Python (`venv`, `pyproject.toml`, `pytest`). `GameRepository` amb SQLite via `sqlite3` estàndard — l'equivalent lleuger d'H2. *Lliurament:* Capa d'abstracció d'ingesta amb persistència real en BD local.
* **Setmana 6 (Testing, Mocks i Qualitat de Codi):** Programació a mà de proves amb JUnit 5 i Mockito. Configuració del workflow GitHub Actions per fer fallar si cobertura < 70%. *Exercici Python:* Suite equivalent amb `pytest` + `unittest.mock`. Afegir `pytest` + `ruff` (linter) al workflow CI existent. *Lliurament:* Suite de tests Java + Python amb cobertura mesurable; pipeline CI que valida els dos llenguatges.

**Bloc 2: APIs REST, Output Estructurat i Integració (50% a mà / 50% assistit)**

* **Setmana 7 (APIs REST amb Spring Boot 3 i Persistència):** Disseny a mà de DTOs i contractes; generació assistida dels controladors HTTP que consulten la BD. Queries REST parameteritzades. *Exercici Python:* Crear un endpoint equivalent amb FastAPI (1-2 rutes bàsiques) — veure que el patró Controller/Service/Repository és universal. *Exercici Specs:* Escriure una "API spec" en format markdown: per cada endpoint, definir ruta, mètode HTTP, request body (exemple JSON), response body (exemple JSON), codis d'error. Donar la spec a l'assistent perquè generi els controladors. Verificar que el codi generat compleix la spec executant requests contra els endpoints. *Lliurament:* Endpoints REST en Java que llegeixen/escriuen a BD; prototip FastAPI equivalent.
* **Setmana 8 (Python, Pydantic i Output Estructurat amb LLMs):** Pydantic models per validar sortides d'LLM. Connexió amb l'API de Claude/OpenAI. System prompts i few-shot per forçar output JSON. *Exercici Eines IA (MCP basics):* Instal·lar i configurar un MCP server existent (`mcp-server-sqlite` o `mcp-server-postgres`) per connectar l'agent (Claude Code / Cursor) directament a la BD de GamePulse. Demostrar que l'agent pot fer queries SQL sense que el developer copiï resultats manualment. Entendre el protocol: l'agent descobreix eines disponibles, les crida amb paràmetres, i rep resultats. *Nota:* Python ja no és nou — l'estudiant porta 7 setmanes fent exercicis en Python. *Lliurament:* Servei Python (FastAPI) que converteix consultes en JSONs estructurats via LLM; MCP server connectat a la BD local.
* **Setmana 9 (Error Handling, Logging i Integració entre Serveis):** Disseny a mà de la gestió d'excepcions; retry bàsic amb backoff exponencial (sense frameworks pesats). Logging estructurat (JSON) tant a Java (SLF4J + Logback) com a Python (`structlog`). Integració Java ↔ Python via HTTP: gestió d'errors parcials, timeouts, i debugging de problemes d'integració reals. *Exercici Eines IA (MCP pràctic):* Crear un MCP server senzill en Python que exposa una eina `search_logs(query, severity, last_minutes)` — l'agent pot consultar els logs estructurats per ajudar a debugar problemes d'integració. L'estudiant veu que un MCP server és un wrapper HTTP sobre una funció Python amb un schema JSON. *Lliurament:* Serveis Java i Python comunicant-se amb gestió d'errors robusta i logs interpretables; MCP server de logs funcional.
* **Setmana 10 (Interfície Streamlit, Integració i Testing End-to-End):** Introducció a Streamlit: dashboard bàsic que consumeix el backend Java via REST. Formularis de cerca, taules de resultats, visualització simple. Workflow GitHub Actions ampliat per testejar Python (pytest + ruff). *Exercici Specs:* Escriure una spec del dashboard en text: wireframe ASCII del layout, descripció de cada component, fluxos d'interacció. L'agent genera l'Streamlit a partir de la spec; l'estudiant compara amb el wireframe i itera. *Lliurament:* Dashboard Streamlit funcional que opera sobre l'API REST; CI que valida Java i Python.

**Bloc 3: Knowledge Engineering, Autenticació i Seguretat (30% a mà / 70% assistit)**

* **Setmana 11 (Knowledge Engineering: Estructurar Informació per a IA):** Teoria: per què la IA dóna respostes incorrectes quan la informació no està ben estructurada. Exercici pràctic: agafar les patch notes reals d'un joc (PDF/HTML) i organitzar-les en una wiki estructurada (markdown amb metadades: data, versió, heroi afectat, tipus de canvi). Chunking intel·ligent: per què tallar un document en trossos importa, com escollir la mida i l'overlap. Configurar Qdrant en Docker i indexar la wiki. *Exercici Python:* Parser de PDF → markdown estructurat amb metadades. Script d'indexació a Qdrant. *Diferència amb RAG clàssic:* No construïm un pipeline de zero — entenem els conceptes per saber configurar i depurar eines que ja existeixen (Notion AI, Cursor @docs, Glean, etc.). *Exercici Eines IA (Trobar Skills i MCP Servers):* Buscar i avaluar eines existents per al projecte: MCP server per a la BD, `.cursorrules` per Spring Boot/FastAPI, MCP server per a Qdrant. Instal·lar les que passin l'avaluació, documentar-les al `CLAUDE.md`. Veure la secció "Com Trobar i Avaluar Skills" al pla general. *Lliurament:* Wiki estructurada de patch notes indexada a Qdrant; script d'ingesta reproduïble; skills i MCP servers del projecte documentats.
* **Setmana 12 (Knowledge Retrieval i Anti-al·lucinació):** Cerca híbrida BM25 + semàntica sobre la wiki indexada. Prompts de restricció: l'LLM només pot respondre amb informació de la wiki, amb citació obligatòria de font i secció. Exercici d'avaluació: 15 preguntes amb respostes de referència (ground truth); mesurar fidelitat amb pytest. Tècniques anti-al·lucinació: "si no trobes la informació, digues que no ho saps". *Exercici Specs:* Escriure una spec de comportament del retrieval: "Donada la pregunta X, ha de retornar la informació Y del document Z." Convertir-la en tests automatitzats. *Lliurament:* Sistema de retrieval amb citació obligatòria, anti-al·lucinació i suite d'evals bàsica.
* **Setmana 13 (Autenticació, Autorització i Seguretat Web):** Spring Security basics: login amb usuari/password, JWT tokens per protegir l'API REST. Protegir endpoints amb `@PreAuthorize` i roles (USER vs ADMIN). CORS, CSRF, headers de seguretat. Hashing de passwords amb bcrypt. *Exercici Python:* Protegir els endpoints FastAPI amb JWT (`python-jose`). *Lliurament:* API REST protegida amb JWT; dashboard Streamlit amb login; endpoints de knowledge retrieval accessibles només per usuaris autenticats.
* **Setmana 14 (SQL Avançat i PostgreSQL):** Migrar d'H2 a PostgreSQL (en Docker). Disseny de BD normalitzada: taules relacionades (Games, Patches, Players) amb foreign keys. Migrations amb Flyway. Queries SQL reals: JOINs, GROUP BY, subqueries, window functions bàsiques. Indexes i `EXPLAIN ANALYZE` — per què una query és lenta? *Exercici:* Trobar i optimitzar una query N+1 generada per JPA. *Lliurament:* BD PostgreSQL normalitzada, migracions automàtiques, queries optimitzades amb evidència d'EXPLAIN.

**Bloc 4: Agents, Docker i Specs d'Agent (20% a mà / 80% assistit)**

* **Setmana 15 (Fonaments d'Agents i Arquitectura):** Disseny a mà del patró d'agents: tool-use loop, role prompts i guardrails. Construcció d'un agent funcional amb un framework (Claude Code SDK, OpenAI Agents SDK, o LangGraph — escollir un). Observabilitat bàsica d'agents (traces amb LangFuse). *Exercici Specs (OpenSpec/SpecKit):* Documentar l'agent formalment: role prompt, llista d'eines amb input/output schema, guardrails, format de resposta, exemples d'interacció. *Exercici Eines IA (Tool Use):* Entendre que els agents funcionen amb un loop: prompt → LLM decideix quina eina cridar → executa eina → rep resultat → LLM decideix si ja ha acabat. Dissenyar l'schema d'eines per als agents de GamePulse: l'Agent Quantitatiu té eines `query_games(filters)`, `get_stats(appId)`; l'Agent de Balanç té eines `search_patches(query)`, `get_patch_detail(id)`. Connexió amb MCP: les eines d'un agent i un MCP server segueixen el mateix patró (nom, input schema, output). *Lliurament:* Agent Quantitatiu i Agent de Balanç funcionant amb spec documentada i tool schemas explícits.
* **Setmana 16 (Orquestració Multi-Agent i Eval-Driven Development):** Orquestrar els dos agents per respondre preguntes complexes. Ampliar dataset d'evals a 25+ preguntes amb respostes de referència i criteris d'avaluació explícits. Mètriques automàtiques al CI: pytest + evals que bloquegen el merge si fidelitat < 80%. *Exercici Specs:* Spec de l'orquestrador: "donada la pregunta X, l'orquestrador ha de decidir si la redirigeix a l'agent de stats, al de knowledge, o a tots dos; el format de resposta ha de ser Y". Convertir la spec en tests. *Lliurament:* Comitè d'agents orquestrat amb evals al CI i spec de comportament testejable.
* **Setmana 17 (Docker i Contenidors):** Introducció a Docker: `Dockerfile`, `docker build`, `docker run`. Dockeritzar el backend Java i el servei Python. `docker-compose.yml` que arrenca tota la plataforma: PostgreSQL + Qdrant + Java + Python + Streamlit. Networking entre contenidors. Volums, health checks, environment variables. *Lliurament:* `docker-compose up` arrenca tot el sistema amb una sola comanda.
* **Setmana 18 (Spec-Driven Development: Feature Completa amb Agent):** Exercici pràctic integrador: l'estudiant rep un requisit de negoci nou ("afegir endpoint de comparació de dos jocs") i ha de:
  1. Escriure la spec completa: endpoint, input/output, lògica, edge cases, tests esperats.
  2. Donar la spec a un agent de codi (Claude Code / Cursor) perquè implementi.
  3. Revisar el codi generat (code review, com S4).
  4. Executar els tests que havia definit a la spec.
  5. Iterar spec → generació → review fins que tot passi.
  *Exercici Eines IA (Skills i Hooks):* Crear un skill personalitzat per a Claude Code (`/review-gamepulse`) que encapsula el workflow de code review específic del projecte: verifica convencions del `.cursorrules`, comprova que no hi ha secrets, valida que els tests existeixen per cada fitxer modificat. Configurar un hook `pre-push` que executa els evals automàticament. *Avaluació:* Es mesura la qualitat de la spec (claritat, completesa), no la del codi generat. Una bona spec + agent genera codi correcte al primer o segon intent. Una spec vaga requereix 5+ iteracions. *Lliurament:* Feature completa implementada per agent amb spec documentada; skill `/review-gamepulse` funcional; informe de quantes iteracions van ser necessàries i per què.
